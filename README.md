# XUI2

XUI2 将原面板拆成管理端和被控端，使用 HTTPS Web API 管理多台被控端。管理端保存账号、共享流量限额、计费方式与历史汇总；被控端运行 Xray，在本机执行账号操作并记录本机流量。两种角色使用同一份程序，由安装时写入的 `XUI_ROLE` 决定。此项目按全新部署设计，不读取旧版 xui 的远程 SSH 配置。

## 安装

支持 Linux amd64、arm64，以 root 运行：

```bash
bash <(curl -fLsS https://raw.githubusercontent.com/small32/XUI2/main/install.sh)
```

安装脚本提示选择 `1) 管理端` 或 `2) 被控端`。更新时默认保留当前角色；已有数据库不能原地切换角色。脚本优先下载 XUI2 Release；没有可用 Release 时，会从 `main` 克隆源码、下载 Go 工具链与 Xray 并在本机编译。首次安装会生成 HTTPS 证书，设置管理员用户名、密码和面板端口。

被控端安装结束会显示 API 令牌和证书 SHA256 指纹。令牌也保存在仅 root 可读的 `/etc/xui/agent.env`；证书和私钥位于 `/etc/xui/panel.crt` 与 `/etc/xui/panel.key`。在管理端的“被控端管理”填写被控端的 `https://主机:面板端口`、令牌、订阅地址和指纹。使用公开可信的证书时可不填指纹。请先确保管理端可以连接被控端的 HTTPS 面板端口。

管理端默认不会启动 Xray；启用本机代理时仅启动本机代理，不启动受管账号入站。被控端只接受管理员网页登录；端口号账号只能登录管理端，用户名为端口号、密码为该入站的服务密码。入站用户只可查看自己的账号、订阅、流量汇总、节点明细和月度历史。

## 上级服务器与本机代理

上级服务器继续通过“面板设置 → xray 相关设置 → xray 配置模版”手动填写出站、认证信息、传输配置及路由。保存并重启面板后加载；不再提供独立的上级服务器表单，也不自动生成或覆盖上级出站及路由。本机代理复用模板中的路由规则和默认出站，因此需要将普通 TCP/UDP 流量路由到实际的上级出站。

勾选“允许本机使用上级服务器代理”后保存并重启，本机 HTTP 代理监听 `127.0.0.1:10809`，SOCKS5 监听 `127.0.0.1:10808`。菜单下载、apt、面板证书续期服务和新登录终端自动使用系统代理；已有终端运行 `source /etc/profile.d/xui-proxy.sh` 加载。仅支持代理的程序使用这些设置，不接管防火墙或全机 TCP/UDP。上级域名需要本机能够解析；HTTP 代理和 `socks5h` 会将访问目标的域名交给上级解析。

关闭本机代理后保存并重启，会清理 XUI 生成的环境、apt 和证书续期代理配置；已有终端需重新登录，或执行 `unset http_proxy https_proxy HTTP_PROXY HTTPS_PROXY all_proxy ALL_PROXY no_proxy NO_PROXY`。本机代理使用独立标签，不计入现有入站账号额度；服务器网卡和上级账号仍会产生实际流量。

被控端“系统状态”的“网络流量”卡片横排显示当前上传/下载速度、当月累计上传/下载量及总流量，使用 | 分隔。累计量独立统计非回环网卡，包括本机系统代理流量；后台每 10 秒保存，无需保持页面打开，面板及服务器重启后保留，按上海时区切换月份。统计从首次启用采集开始，之前的历史用量无法追溯，不参与账号共享额度结算。

## 账号、流量与重试

管理员在管理端创建、修改或删除入站后，管理端为每台启用的被控端记录独立同步任务并立即发送。失败任务留在数据库中，下一次心跳重试，页面会列出节点和错误。新增被控端时，会下发当前全部账号。被控端用管理端账号 ID 定位本地记录；修改端口时原位更新，保留已有流量。各被控端证书路径从自身面板设置提取。

管理端下发配置时，若被控端同端口已有本地入站或其他受管入站，直接以管理端配置覆盖，并绑定到当前管理端账号，保留已有流量计数。账号修改端口时如目标端口已被占用，也覆盖该端口配置并合并原有流量计数；重复下发不会重复累计。

在管理端新增或编辑账号时，可选择“所有被控端”或指定多个下发节点。指定节点的选择会持久保存，心跳、重试、重置和订阅均遵循此选择；取消节点后会清理该节点上的此受管账号。停用节点暂不接收普通配置，重新启用后补发所选账号。已有账号默认仍选择所有被控端，包含以后新增的节点。

账号编辑窗口提供各被控端的协议标签页。勾选“为此被控端单独设置协议”后，可设置该节点的协议、传输、TLS 与监听地址；未勾选的节点使用默认连接设置。备注、端口、总流量、计费方式、到期时间共用账号设置，Trojan、Shadowsocks、HTTP、SOCKS 使用上方“账号统一密码”；VLESS、VMess 的 UUID 保留各自配置。每个节点按自身连接设置计算配置版本，心跳不会将节点专属协议改回默认协议。

生成订阅时合并所选启用节点的实际链接，二维码窗口按节点名称和实际协议分别展示二维码。HTTP/SOCKS 链接使用订阅转换器支持的类 Telegram 链接格式，参见 [subconverter 支持格式](https://github.com/tindy2013/subconverter/blob/master/README.md)。

默认每 10 分钟读取一次所有被控端流量，可设置更长间隔，也可在页面立即刷新。流量限额由所有被控端共同消耗；合计上传和下载达到管理端账号限额时，管理端向所有被控端下发停用。未超限时不修改启用状态。过期账号同样停用。手动停用与超限停用分别记录原因。某个节点断线、账号版本落后或数据过期时，页面显示“未确认”及最近错误；断线期间实际用量可能超过共享限额，连接恢复后会补采并处理。

被控端管理可设置每个节点的“流量倍率”，默认 1，支持 0 和非负小数。管理端按原始上传、下载量分别乘以倍率计算节点用量、流量汇总及共享额度，结果四舍五入到字节；修改倍率会重新计算当前周期的全部已采集流量。被控端原始计数不变，重复读取不会叠乘。月度历史按结算时倍率保存，后续修改倍率不会改变已结算历史。

被控端本地创建或通过跨节点复制生成的入站也会被采集，在“流量汇总”按节点单独显示，来源标为“节点名称（本地入站）”。本地入站端口与管理端受管账号相同时，其用量合并到该账号的共享额度及节点明细；没有匹配受管账号的本地入站按节点单独展示。可以点击“读取最新被控端流量”立即采集，读取失败时保留上次用量并标为“未确认”。此功能需要管理端与被控端同时更新。

按月计费的账号在每月切换时留档并重置计数；累计计费账号不会自动清零。被控端会独立保存月度原始快照，管理端断线后可通过幂等重置接口补取并汇总历史。若被控端本身跨月离线、无法还原某个月的原始流量，接口明确报错，不会把多个自然月的数据静默归入一个月。月度重置全部完成后，原先因超限停用的账号才会恢复启用。管理端数据库中的操作队列及被控端的重载标记用于处理网络故障和 Xray 重启失败。

已有节点的 API 地址不可直接修改。更换服务器时，先删除旧节点并确认远端账号清理完成，再添加新节点；修改同一服务器的证书指纹不会清空待同步任务。正常删除被控端时，管理端先删除其受管账号；如果节点不可达或还有待同步任务，节点仍保留在管理端。旧服务器已无法连接时，可使用“强制移除”，但必须自行停机或清理旧服务器上的账号；强制移除不检查节点连接或月度任务状态，直接清除该节点及其全部同步任务、当前流量记录；已完成的历史流量快照保留，未完成的月度结算不再补采。

## 被控端 API

管理端的“被控端管理”页面提供独立的“被控端入站设置”标签页，其中按被控端在管理列表中的名称分标签读取全部入站（包括本地创建的入站）。可以全选或勾选部分入站，再选择一个或多个其他被控端同步。每个目标、端口单独显示成功或失败，失败项可重新选择后再同步。管理端和被控端都需要更新到支持此功能的代码版本。

此操作将配置复制为目标端的本地入站，不复制来源的已用流量或管理账号 ID。目标同端口默认跳过；勾选覆盖时仅覆盖本地入站，并保留目标已有流量。受管入站仍通过管理端原有账号同步机制配置。文件证书路径取自目标端面板设置，保存后立即请求重载 Xray。

API 位于被控端 HTTPS 面板的 `/api/v1`，使用独立的 `Authorization: Bearer <API令牌>`。明文 HTTP、缺失令牌和错误令牌均被拒绝。自签名证书由管理端按 SHA256 指纹校验。API 仅供管理端后端调用；浏览器不保存被控端令牌。

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/capabilities` | 检查 API 版本 |
| GET | `/inbounds` | 查询全部受管账号 |
| GET | `/inbounds/all` | 查询全部入站，包含本地入站 |
| PUT | `/inbounds/copy/{port}` | 复制配置为本地入站，支持覆盖本地同端口配置 |
| GET | `/inbounds/{port}` | 查询指定端口账号 |
| PUT | `/inbounds/{port}` | 按管理端账号 ID 新增或修改 |
| DELETE | `/inbounds/{port}` | 删除指定账号 |
| GET | `/traffic` | 查询各账号本机流量及状态 |
| POST | `/inbounds/{port}/disable` | 按超限或过期原因停用 |
| POST | `/inbounds/{port}/traffic/reset` | 幂等重置并返回重置前流量 |

新增或修改示例：

```http
PUT /api/v1/inbounds/34872
Authorization: Bearer <token>
Idempotency-Key: <operation-id>
Content-Type: application/json

{"managerAccountId":42,"managerRevision":"<64位配置摘要>","port":34872,"protocol":"trojan","settings":"{\"clients\":[{\"password\":\"secret\"}]}","streamSettings":"{}","sniffing":"{}","remark":"客户 A","enable":true,"total":107374182400,"monthlyReset":true}
```

流量响应示例：

```json
{"observedAt":1790121600,"inbounds":[{"accountId":42,"port":34872,"up":1200000,"down":3400000,"enabled":true,"disabledBy":"","managerRevision":"<64位配置摘要>"}]}
```

月度重置请求包含 `accountId`、上一自然月编号 `period`（如 `202609`）及唯一 `operationId`。被控端对同一月份保存一次快照，重复调用返回相同的重置前用量，不会再次清零。

## 开发

```bash
go test ./...
go build ./...
bash -n install.sh
```

Release 工作流仅在推送版本标签或手动触发时运行。`config/version` 当前为 `0.2.8`；提交到 `main` 不会自动发布 Release。

流量汇总的节点明细同时显示流量倍率、实际用量与计费用量（原“用量”）；上传、下载为节点原始计数。共享额度及自动超限停用按各节点倍率后的用量之和计算，超限后向所有下发节点发送停用配置。

入站详细信息在节点名称旁显示“节点倍率 N×”，倍率以红色加粗大字展示；节点信息每行最多三个，超过自动换行，窄屏自动减少列数。


## 管理端客户端服务（0.2.7）

仅 `XUI_ROLE=manager` 注册客户端接口和安装包管理接口。被控端不注册接口、不显示客户端设置或下载区，也不新增客户端数据表；现有被控端无需升级。客户端服务默认开启，可在面板设置 → 面板配置中关闭，独立于网页登录开关。

客户端填写管理端前缀，例如 `https://small32.top:8201/`；有面板路径前缀时填写完整地址，例如 `https://example.com/panel/`。Webservices 在此前缀后拼接 `api/client/v1/`。面板根据浏览器当前登录地址显示服务地址，支持管理员保存外部访问地址用于反向代理。安装包不需要绑定固定管理端。

### 客户端接口约定

| 方法 | 相对地址 | 认证 | 说明 |
| --- | --- | --- | --- |
| GET | `api/client/v1/info` | 无 | API 版本、XUI 版本、已配置外部地址和客户端默认值 |
| POST | `api/client/v1/auth/login` | 端口号和密码 | JSON `{"port":"18888","password":"账号密码"}` |
| POST | `api/client/v1/auth/refresh` | 刷新令牌 | JSON `{"refreshToken":"..."}`，旋转访问和刷新令牌 |
| POST | `api/client/v1/auth/logout` | Bearer | 注销当前会话 |
| GET | `api/client/v1/account` | Bearer | 当前账号账单、状态和订阅配置版本 |
| GET | `api/client/v1/subscription/clash` | Bearer | 直接返回 Clash/Mihomo YAML，不使用第三方转换器 |
| GET | `api/client/v1/downloads` | Bearer 或有效面板登录 | 已发布安装包列表 |
| GET / HEAD | `api/client/v1/downloads/:id` | Bearer 或有效面板登录 | 托管安装包下载或外部分发链接跳转 |

登录响应包含 `accessToken`、`refreshToken`、`tokenType=Bearer`、`expiresAt`、`refreshExpiresAt`。访问令牌有效期 24 小时，刷新令牌有效期 30 天；刷新后旧令牌失效。数据库只保存令牌哈希；账号改密、删除或关闭客户端服务后原登录不能访问接口。停用账号仍可以登录查询账单，不能获取可用订阅。登录失败沿用面板 IP 限流。

客户端请求受保护接口时设置 `Authorization: Bearer <accessToken>`。成功响应为直接 JSON，错误为 `{"error":"原因"}` 和相应 HTTP 状态码（401 登录失效、403 账号不可代理、422 配置不可转换、429 限流）。接口默认禁止缓存，不提供跨站网页登录权限。

`account` 返回 `port`、`remark`、`usedBytes`、`actualUsedBytes`、`totalBytes`、`remainingBytes`、`unlimited`、`expiresAt`、`status`、`canProxy`、`monthlyReset`、`observedAt`、`stale`、`configVersion`、`renewalDays=[14,7,3]`。流量字段单位为字节，时间字段为 Unix 秒；无到期时间返回 `expiresAt=null`，不限量返回 `remainingBytes=null`。用量使用管理端当前计费周期的倍率汇总，包含同端口本地入站及已保留的历史节点计数；`actualUsedBytes` 为原始计数。统计读取缓存，不触发逐节点网络查询。客户端建议每 60 秒刷新；节点数据滞后以 `stale` 标识。

账号状态包含 `active`、`disabled`、`overlimit`、`expired`、`no_nodes`、`invalid_config`。客户端必须按 `canProxy` 决定是否启动代理。到期提醒由客户端根据 `expiresAt` 和 `renewalDays` 执行并按账号、到期时间、档位去重；客户端退出时不提供后台通知。原有管理端超限停用规则保持生效。

订阅从管理端保存的配置生成，只包含当前启用、且被账号选择下发的节点，支持各节点不同协议。节点离线不影响已保存配置生成。支持 Shadowsocks、Trojan、VMess、VLESS、HTTP、SOCKS，以及适用协议的 TCP、WebSocket、gRPC、HTTP/2 和 TLS；暂不转换 Reality、旧 XTLS、KCP、QUIC、TCP HTTP 伪装及不兼容的组合，返回明确错误。订阅提供 `Subscription-Userinfo`（计费用量）、`Profile-Update-Interval` 与 ETag；`configVersion` 是实际订阅内容的 SHA256。

配置默认 `mode: rule`、`ipv6: false`、DNS IPv6 关闭、`tun.enable: false`、`tun.stack: mixed`，配置管理端直连规则、内网直连、中国 IP 直连及其他流量走节点选择组。系统代理、自启、静默启动及用户选择的规则／直连／全局模式由后续客户端实现和保存；订阅更新不应覆盖用户选择。

### 安装包管理及下载

面板设置支持上传 Windows `.exe/.msi/.zip`、macOS `.dmg/.pkg/.zip`、Android `.apk`、iOS `.ipa`，也可保存 TestFlight／App Store 等 HTTP(S) 外部分发链接。可填写平台、架构、版本，独立发布、取消发布或删除。仅管理员允许管理安装包。最大上传大小 1GB，服务端生成存储名并计算 SHA256；目录为 `/etc/xui/client-packages`，数据库记录存于原面板数据库，面板升级不会覆盖这些数据。使用反向代理时其上传限制需允许所需包大小。

管理端入站列表顶部、总用量下方显示已发布安装包，不提供打开客户端链接。Android／iOS 下载入口仅负责分发，不代表已构建这两个平台的定制客户端。

手动上传的托管安装包在单个管理端进程内按登录账号限制一个有效下载流，客户端令牌与该账号面板会话共用下载名额；不同账号可分别下载。拒绝多段 Range，单段 Range 忽略并发送完整文件，永不返回 206；下载完成或连接断开后释放名额。HEAD 仅返回文件信息，不占用下载名额。外部分发链接不受此限制。反向代理须关闭该下载路径的缓存及响应缓冲，防止代理提前取完文件绕开并发限制；多实例部署需另外实现共享下载名额。


### 自动获取 GitHub 客户端 Release

管理端“面板设置 → 面板配置 → 客户端服务”可启用“自动获取 GitHub 客户端”，手工填写仓库的 Release 地址，例如 `https://github.com/small32/SClash/releases/`，并保存 GitHub 访问令牌。私有仓库需要令牌；推荐 fine-grained PAT，仅授权目标仓库的 `Contents: Read-only`。令牌只保存在管理端数据库，浏览器仅收到“已配置”状态；密码框留空保留已有令牌，也可明确清除或替换。

启用后，用户进入入站列表时自动读取最新正式版（不含草稿／预发布）并合并显示可识别的 Windows、macOS、Android、iOS 安装包。元数据缓存 10 分钟，下一次访问时检查更新；管理员可点击“检查最新版”立即刷新。检查失败保留最近成功的列表，并在管理员检查结果中显示原因。仓库未提供的平台不会生成虚假的下载入口。手动上传和外部分发链接仍可使用。

GitHub 下载方式支持 `auto`（默认）、`direct`、`relay`。自动模式下，未启用“允许本机使用上级服务器代理”时，下载链接直接指向 GitHub Release；启用该选项后默认经管理端的本机上级代理中转。管理员也可明确选择直连或中转。

私有仓库直连在点击时由管理端携带 PAT 获取临时下载地址，然后浏览器直接从 GitHub 下载；链接不缓存到数据库，PAT 不返回浏览器、不转发 CDN。GitHub 资产接口若只返回文件流而不提供临时地址，会提示使用“中转”入口。入站列表在直连下载旁提供可选的中转链接。直连的数据流不经过 XUI，其下载并发由 GitHub 决定。

中转下载不落盘，每个登录账号最多 5 个并发下载线程，支持单个 Range 字节区间及 If-Range，转发 GitHub 的 200、206、416 状态和 Content-Range；第 6 个并发请求返回 429。不同账号独立计数。代理开启时，中转请求使用本机上级代理；关闭时直接由管理端连接 GitHub。手工上传安装包保持原单流规则。

新增 `POST xui/client/github-release` 为仅管理员可用的手动检查接口，JSON `{"refresh":true}` 强制刷新；`GET api/client/v1/release-links/:assetID` 获取私有临时链接；`GET/HEAD api/client/v1/release-downloads/:assetID` 按当前方式重定向或中转，`?relay=1` 明确请求中转。Release 地址通过 `githubReleaseUrl`、开关通过 `githubReleaseEnable`、下载方式通过 `githubDownloadMode` 保存；`githubToken` 仅用于提交新令牌，设置读取只返回 `githubTokenConfigured`。
